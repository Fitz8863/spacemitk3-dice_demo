# YOLOv10 手势检测工程（K3 板端）

## 结论先行
在 `/home/heweijie/spacemit-k3-dev/projects/dice-game/yolov10_objdetect/` 新建 C++ 工程，**复用 yolov8_objdetect 的全部管线骨架**（GStreamer 硬解采集 → OpenCL 前处理 → SpaceMIT EP 推理 → RTSP 推流，三线程 + latest-only 队列 + config.json），只把检测器换成 YOLOv10 的 `[1,300,6]` end-to-end 输出，并删除黑线分界与 LLM 两条链路。

## 模型事实（已在开发机实测钉死）
- 输入 `images [1,3,640,640]` FLOAT（/255 归一化，OpenCL 前处理不变）
- 输出 `output0 [1,300,6]` FLOAT：每行 `(x1,y1,x2,y2,conf,class_id)`，640 letterbox 域像素坐标、conf 已 sigmoid、行序按 conf 降序、**免 NMS**
- 34 类 HaGRID 手势；第 33 类 `no_gesture` 默认过滤不画框
- opset 24（板端 ORT 1.24.2 可跑）+ PPQ QDQ 量化
- ⚠️ ORT 图优化须 **ORT_ENABLE_BASIC**（EXTENDED/ALL 会因 INT8/UINT8 zero_point 混用报类型推断错）；初始化失败时自动降级 ORT_DISABLE_ALL 重试一次

## 执行步骤
1. **git 建仓**：`git init -b main` + .gitignore + 基线提交（现有 model/），登记 `~/.zcode/git-safety/ledger.json`
2. 落代码（上表全部文件），编译细节 commit 一次
3. **板端编译**（ssh）：`cmake -S . -B build -DCMAKE_BUILD_TYPE=Release`（OpenCV_DIR 按板端 yolov8 工程同款）
4. **板端验证**（先 `fuser /dev/video1` 确认摄像头没被其它进程占用）：
   - `--self-test --no-display --no-rtsp`（OpenCL+EP 全链路自测）
   - `--no-display --max-frames 60 --no-rtsp` 真机短跑，看检测数与 infer_ms；若有检不出/置信度异常，用 `--no-ep` 对照 CPU 排查
   - 拉起 RTSP，`ffprobe rtsp://127.0.0.1:8554/rps/det` 验流 + 抓帧核对画框
5. 验证中发现的问题修复后补 commit，README 补验证记录

## 风险与边界
- 板子只 commit 不 push；不动板上其它工程与常驻进程（dice-game 服务、mediamtx 配置均不碰）
- 摄像头被占用时只报不抢，等用户处理
- EP 对该量化图的兼容性待板端实测（INT8/UINT8 混用是新图特征），已留 `--no-ep` 对照路径
