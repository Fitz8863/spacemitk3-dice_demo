# asr_zipformer 参数说明

`backend/components/asr_zipformer/config.json` 是语音识别引擎的组件层配置（JSON 无注释，本文档就是它的注释）。**改任何字段后需重启后端**（`stop_web.sh && start_web.sh`）；语音的开关和触发词表不在组件这里，在游戏 manifest 的 `asr` 节（见 `backend/games/dice/参数说明.md` 第 3 节，那份热加载）。

引擎本体是仓库内的 `asr/zipformer-streaming`（C++ 真流式 Zipformer），构建与 JSONL 事件契约见 `asr/zipformer-streaming/AGENTS.md`。

```json
{
  "schema_version": 1,
  "runtime": {
    "binary": "asr/zipformer-streaming/build/stream_asr",
    "working_dir": "asr/zipformer-streaming",
    "model_dir": "sherpa-onnx-streaming-zipformer-bilingual-zh-en-2023-02-20",
    "capture": {
      "device": "default",
      "sample_rate": 16000,
      "channels": 1,
      "format": "S16_LE"
    },
    "vad": {
      "enabled": true,
      "rms": 400,
      "pause_ms": 600,
      "max_ms": 8000
    },
    "cpu_affinity": "",
    "start_timeout_seconds": 15,
    "terminate_grace_seconds": 5
  }
}
```

## 字段说明

### 路径

| 字段 | 当前值 | 说明 |
|---|---|---|
| `schema_version` | `1` | 固定值，校验用 |
| `runtime.binary` | `asr/zipformer-streaming/build/stream_asr` | 引擎二进制，**仓库相对路径**（不允许绝对路径和 `..`，校验时做防穿越检查；文件在板上编译产出，`build/` 不入库） |
| `runtime.working_dir` | `asr/zipformer-streaming` | 子进程工作目录，同样仓库相对 |
| `runtime.model_dir` | `sherpa-onnx-...-2023-02-20` | 模型目录，**相对 working_dir**（模型文件不入库，下载方式见 `asr/zipformer-streaming/README.md`） |

### capture（音频采集）

| 字段 | 当前值 | 说明 |
|---|---|---|
| `device` | `default` | ALSA 采集设备。`default` 走 PipeWire 跟随**系统默认输入**——换麦克风在桌面声音设置里选，不用改这里。也可直连硬件（如 `plughw:CARD=C920,DEV=0`，绕过 PipeWire 延迟更低） |
| `sample_rate` | `16000` | **引擎契约，只允许 16000**（改了配置校验直接报错） |
| `channels` | `1` | 引擎契约，只允许单声道 |
| `format` | `S16_LE` | 采样格式，当前唯一支持值 |

### vad（断句——说出一句、停顿后出整句）

| 字段 | 当前值 | 说明 |
|---|---|---|
| `enabled` | `true` | 关掉则不出整句（只剩流结束时一整段），语音确认依赖整句，**不要关** |
| `rms` | `400` | 静音门限（s16 量级）。**环境嘈杂/老是出垃圾字 → 调高（如 800）**；说话小声识别不断句 → 调低 |
| `pause_ms` | `600` | 停顿多久断句。**想要"说完确认更快跳转"可降到 400~500**，代价是说话中途换气可能提前断句 |
| `max_ms` | `8000` | 单句最长时长，到点强断（防长语音无停顿），文本不丢接着下一句 |

体感延迟参考：说完一个词到它出现在整句里 ≈ 0.4~0.5s 推理 + `pause_ms` 停顿判定。

### 进程管理

| 字段 | 当前值 | 说明 |
|---|---|---|
| `cpu_affinity` | `""` | 可选绑核，如 `"0,3"`（spawn 时用 taskset 包装，把 ASR 与其他负载隔离）。空 = 不绑 |
| `start_timeout_seconds` | `15` | 模型加载就绪的等待预算（stderr 首行视为就绪）。超时不报错只记日志继续跑 |
| `terminate_grace_seconds` | `5` | 停麦时先停采集让引擎自然收尾的宽限，超时才强杀 |

## 未暴露的引擎参数（有意为之）

引擎 CLI 还有 `--cpu`/`--encoder int8.onnx`（纯 CPU 降级）、`--threads`（CPU 线程数）、`--ep-disable-conv`（EP 禁用 Conv）等调试开关，集成固定走 EP + q.onnx 推荐路径，没有暴露进 config。需要降级模式时改 `provider.py` 里 `asr_argv` 的拼装。

## 其他须知

- 会话生命周期由回合驱动：创建回合时 spawn `arecord | stream_asr --pcm --jsonl` 子进程对，回合结束（或取消/被新回合顶替）约 2 秒内自动停麦。
- ASR EP 线程默认落在 X100 通用核（0-7，模型包官方推荐配置），与后端主进程同簇；RTF≈0.24 占用约 1 核，紧张时用 `cpu_affinity` 隔离。
- 组件无 lifecycle（不进 `start_web.sh`），健康检查 = binary 可执行 + 模型目录存在，见 `/api/health` 的 `asr_zipformer` 条目。
