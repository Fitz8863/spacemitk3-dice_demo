# vision_yolov8_adjudicator 参数说明

视觉裁决器涉及**两个配置文件**，职责分离（JSON 无注释，本文档就是它们的注释）：

1. **组件配置** `backend/components/vision_yolov8_adjudicator/config.json` —— provider 生命周期与 LLM 复核凭证
2. **runtime 硬件配置** `vision/yolov8_adjudicator/config.json` —— 摄像头、推理线程、RTSP/WebRTC 推流

游戏级参数（模型、类别、规则、prompt、超时、稳定帧）**不在这两个文件里**，在游戏 manifest 的 `vision_profile`（见 `backend/games/dice/参数说明.md` 第 5 节）。

**优先级规则**：实际每局裁决时，游戏 profile 的 `vision.model` / `vision.stable_frames` / `vision.confidence`（缺省取 `conf`）/ `multi_view.views[].camera` 会以命令行参数下发给 runtime，**覆盖** runtime 硬件配置里的同名默认值。runtime config 只是不带 profile 时的兜底。

两个文件都是**改后重启**生效（resident 常驻进程随 `stop_web.sh && start_web.sh` 重启）。

---

## 一、组件配置（backend/components/vision_yolov8_adjudicator/config.json）

```json
{
  "schema_version": 1,
  "runtime": {
    "binary": "vision/yolov8_adjudicator/build/yolov8_camera",
    "working_dir": "vision/yolov8_adjudicator",
    "config": "vision/yolov8_adjudicator/config.json",
    "mode": "resident",
    "prewarm_camera": true,
    "terminate_grace_seconds": 5
  },
  "llm": {
    "endpoint": "https://api.deepseek.com/v1",
    "model": "deepseek-v4-flash-vision-exp",
    "api_key": "sk-…"
  },
  "events": { "protocol": "jsonl-events-v1" }
}
```

| 字段 | 当前值 | 说明 |
|---|---|---|
| `schema_version` | `1` | 固定值 |
| `runtime.mode` | `resident` | `resident`（进程常驻，裁决任务复用，不重复付模型加载/摄像头启动成本）/ `per_request`（每次任务起一个进程） |
| `runtime.binary` | `vision/.../yolov8_camera` | C++ runtime 二进制，仓库相对路径（板上编译产出，`build/` 不入库） |
| `runtime.working_dir` | `vision/yolov8_adjudicator` | 子进程工作目录 |
| `runtime.config` | `vision/.../config.json` | 指向下方第二个文件（runtime 硬件配置） |
| `runtime.prewarm_camera` | `true` | 常驻模式下预启动摄像头，任务来了即采即推流 |
| `runtime.terminate_grace_seconds` | `5` | 停止 runtime 的优雅退出宽限 |
| `llm.endpoint` | `https://api.deepseek.com/v1` | OpenAI 兼容多模态接口地址 |
| `llm.model` | `deepseek-v4-flash-vision-exp` | 复核用模型名 |
| `llm.api_key` | `sk-…` | **密钥就在这个文件里，文件被 Git 跟踪——仓库必须保持私有**；key 不得出现在 web 响应/日志/前端 |
| `events.protocol` | `jsonl-events-v1` | 结构化事件走独立 `--event-fd` 管道（stdout/stderr 只作诊断日志） |

## 二、runtime 硬件配置（vision/yolov8_adjudicator/config.json）

```json
{
  "model": "models/best.q.onnx",
  "camera": "/dev/video1",
  "device": "",
  "width": 1280, "height": 720, "fps": 25,
  "intra_threads": 2,
  "ep_affinity": "14;15",
  "queue_depth": 2,
  "conf": 0.5,
  "focus": 0, "zoom": 160,
  "display_enabled": false,
  "yolov8_enabled": false,
  "divider_detection": false,
  "stable_frames": 30,
  "video": { "webrtc_base_url": "http://100.118.229.28:8889" },
  "rtsp": { "enabled": true, "host": "127.0.0.1", "port": 8554, "path": "/dice" }
}
```

### 采集与画面

| 字段 | 当前值 | 说明 |
|---|---|---|
| `camera` | `/dev/video1` | V4L2 采集设备节点（MJPEG 采集 + 硬件解码） |
| `device` | `""` | 摄像头序号备选写法（`camera` 优先） |
| `width`/`height`/`fps` | 1280/720/25 | 采集分辨率与帧率（实际按设备能力协商到 24fps） |
| `focus` / `zoom` | 0 / 160 | UVC 摄像头的对焦/变焦控制值（0 = 不主动设置） |
| `display_enabled` | `false` | 板端本地窗口显示（无屏部署保持关闭） |

### 推理

| 字段 | 当前值 | 说明 |
|---|---|---|
| `model` | `models/best.q.onnx` | 模型路径（相对 runtime 目录；实际每局用游戏 profile 的 `vision.model` 下发覆盖） |
| `intra_threads` | `2` | CPU 侧会话线程数 |
| `ep_affinity` | `14;15` | SpaceMIT EP 推理线程绑核（**分号分隔**，A100 加速核；实测线程会精确落到这两个核） |
| `conf` | `0.5` | 检测置信度阈值（游戏 profile 的 `vision.confidence`/`conf` 可覆盖） |
| `stable_frames` | `30` | 稳定判定帧数默认值（游戏 profile 覆盖，见 dice 参数说明） |
| `yolov8_enabled` | `false` | **预热/空闲阶段不主动做推理**（省算力，任务来时才开检测） |
| `divider_detection` | `false` | 黑线分界检测辅助（是否启用由游戏 profile 的 `vision.divider_detection` 决定） |
| `queue_depth` | `2` | 帧队列深度（采集-推理-显示之间的背压） |

### 推流

| 字段 | 当前值 | 说明 |
|---|---|---|
| `rtsp.enabled/host/port/path` | true / 127.0.0.1 / 8554 / `/dice` | 推流到本机 mediamtx（浏览器不直连 RTSP） |
| `video.webrtc_base_url` | `http://100.118.229.28:8889` | mediamtx 的 WebRTC 播放基础地址（浏览器页面内嵌画面用它拼 URL；游戏只配自己的 `video.path`） |

## 其他须知

- resident 模式的空闲签名：web 日志持续打 `pipeline prepared=… infer=<冻结值>`——`infer` 冻结是设计行为（空闲不推理），不是卡死。
- 改采集/预处理后必须在板上跑自检：`yolov8_camera --config config.json --self-test --no-display` + 短 `--max-frames` 冒烟（详见 `vision/yolov8_adjudicator/AGENTS.md` 与 README）。
- LLM 复核的裁决优先级（共识/复问/平局保护/回退）由代码与游戏 profile 决定，与这两个文件无关，见 dice 参数说明第 5 节。
