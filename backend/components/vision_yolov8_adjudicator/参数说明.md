# vision_yolov8_adjudicator 参数说明

视觉裁决器涉及**两类配置文件**，职责分离（JSON 无注释，本文档就是它们的注释）：

1. **组件配置** `backend/components/vision_yolov8_adjudicator/config.json` —— provider 生命周期
2. **runtime 硬件配置** `backend/games/<id>/adjudicator_config.json` —— 摄像头、推理线程、RTSP/WebRTC 推流，**每游戏一份**，由游戏 manifest 的 `vision_profile.runtime_config` 必填声明（共享部署默认 `vision/yolov8_adjudicator/config.json` 已于 2026-09-20 删除）

LLM 复核凭证（endpoint/model/api_key）**已迁移到独立的 LLM 组件** `backend/components/llm_openai_compat/`（2026-09-04 大模型模块化），由全局配置 `providers.llm` 槽位指派，见该组件的参数说明。

游戏级参数（模型、类别、规则、prompt、超时、稳定帧）**不在这两类文件里**，在游戏 manifest 的 `vision_profile`（见 `backend/games/dice/参数说明.md` 第 5 节）。

**优先级规则**：实际每局裁决时，游戏 profile 的 `vision.model` / `vision.stable_frames` / `vision.confidence`（缺省取 `conf`）/ `multi_view.views[].camera` 会以命令行参数下发给 runtime，**覆盖**硬件配置里的同名默认值；硬件文件里没写的键回落 C++ 编译期默认值。

两个文件的生效方式不同：

- **组件配置**：改后**重启后端**生效（`stop_web.sh && start_web.sh`）。
- **runtime 硬件配置**（各游戏 `backend/games/<id>/adjudicator_config.json`，manifest 用 `vision_profile.runtime_config` 必填声明）：保存后**下一回合生效，无需重启后端**——文件的 mtime+size 已纳入 runtime 签名，provider 会自动拆旧建新常驻进程（正在运行的一局仍用旧参数）。

## 一、组件配置（backend/components/vision_yolov8_adjudicator/config.json）

```json
{
  "schema_version": 1,
  "runtime": {
    "binary": "vision/yolov8_adjudicator/build/yolov8_camera",
    "working_dir": "vision/yolov8_adjudicator",
    "mode": "resident",
    "prewarm_camera": true,
    "terminate_grace_seconds": 5
  },
  "events": { "protocol": "jsonl-events-v1" }
}
```

| 字段 | 当前值 | 说明 |
|---|---|---|
| `schema_version` | `1` | 固定值 |
| `runtime.mode` | `resident` | `resident`（进程常驻，裁决任务复用，不重复付模型加载/摄像头启动成本）/ `per_request`（每次任务起一个进程） |
| `runtime.binary` | `vision/.../yolov8_camera` | C++ runtime 二进制，仓库相对路径（板上编译产出，`build/` 不入库） |
| `runtime.working_dir` | `vision/yolov8_adjudicator` | 子进程工作目录 |
| `runtime.prewarm_camera` | `true` | 常驻模式下预启动摄像头，任务来了即采即推流 |
| `runtime.terminate_grace_seconds` | `5` | 停止 runtime 的优雅退出宽限 |
| `events.protocol` | `jsonl-events-v1` | 结构化事件走独立 `--event-fd` 管道（stdout/stderr 只作诊断日志） |

（`runtime.config` 指针已随共享默认一起删除——写回会被校验器拒载。）

## 二、runtime 运行配置（backend/games/<id>/adjudicator_config.json，每游戏一份）

dice 读 `backend/games/dice/adjudicator_config.json`（1080p 广角版本给 rps，在 `backend/games/rps/adjudicator_config.json`）。整份替换语义：没写的键回落 C++ 编译期默认值。**这个文件持有 C++ runtime 消费的全部参数**——模型与检测参数（`model`/`conf`/`stable_frames`/`divider_detection`，2026-09-20 从 manifest 迁入）+ 硬件；`class_map`/`grouping`/`expected_count` 等游戏语义仍在 manifest。以下示例即 dice 文件的形状：

```json
{
  "model": "models/best.q.onnx",
  "conf": 0.45,
  "stable_frames": 30,
  "divider_detection": true,
  "camera": "/dev/video1",
  "device": "",
  "width": 1280, "height": 720, "fps": 25,
  "intra_threads": 2,
  "ep_affinity": "14;15",
  "queue_depth": 2,
  "focus": -1, "zoom": 180,
  "video": { "webrtc_base_url": "http://127.0.0.1:8889" },
  "rtsp": { "enabled": true, "host": "127.0.0.1", "port": 8554 }
}
```

### 采集与画面

| 字段 | 当前值 | 说明 |
|---|---|---|
| `camera` | `/dev/video1` | V4L2 采集设备节点（MJPEG 采集 + 硬件解码） |
| `device` | `""` | 摄像头序号备选写法（`camera` 优先） |
| `width`/`height`/`fps` | 1280/720/25 | 采集分辨率与帧率（实际按设备能力协商到 24fps） |
| `focus` / `zoom` | 0 / 160 | UVC 摄像头的对焦/变焦控制值（0 = 不主动设置） |
| `display_enabled` | `false` | 板端本地窗口显示（无屏部署保持关闭） |

### 推理与检测

| 字段 | 当前值 | 说明 |
|---|---|---|
| `model` | `models/best.q.onnx` | 模型路径，**相对本文件所在目录解析**（即 `backend/games/<id>/models/…`；模型文件按游戏存放）。不写回落 C++ 默认 `models/best.q.onnx`——恰是本游戏目录下的同名文件 |
| `conf` | `0.45` | 检测置信度阈值（2026-09-20 起每游戏在此声明；写进 manifest 会被拒载） |
| `stable_frames` | `30` | 稳定判定帧数：连续多少个**有效**帧检测一致才发稳定观测（有效帧 = 已定位分界线 + 每侧恰好期望数量 + 分侧结果与上帧一致，任一不满足即清零） |
| `divider_detection` | `true` | 分界线检测：先认"红蓝地垫分区"（配色抗反光），失败回退印刷深色线。检出的线既是稳定帧门控判据，也是左右归属的切分位置（与 provider 用同一个像素点）；检测不到时该帧不计稳定帧，归属回落 manifest 的 `divider.position`（缺省 0.5） |
| `intra_threads` | `2` | CPU 侧会话线程数 |
| `ep_affinity` | `14;15` | SpaceMIT EP 推理线程绑核（**分号分隔**，A100 加速核；实测线程会精确落到这两个核） |
| `queue_depth` | `2` | 帧队列深度（采集-推理-显示之间的背压） |

### 推流

| 字段 | 当前值 | 说明 |
|---|---|---|
| `rtsp.enabled/host/port/path` | true / 127.0.0.1 / 8554 / `/dice` | 推流到本机 mediamtx（浏览器不直连 RTSP） |
| `video.webrtc_base_url` | `http://127.0.0.1:8889` | mediamtx 的 WebRTC 播放基础地址（浏览器页面内嵌画面用它拼 URL；游戏只配自己的 `video.path`） |

## 其他须知

- resident 模式的空闲签名：web 日志持续打 `pipeline prepared=… infer=<冻结值>`——`infer` 冻结是设计行为（空闲不推理），不是卡死。
- 硬件配置写错键名（如 `ep_afinity` 少个 f）**不会拒载**——C++ 与 Python 两侧解析器都静默忽略未知键；provider 加载该文件时会在 web 日志打一条 `[vision] runtime config …: unknown keys …` 警告（同一文件同一组未知键只警一次，键名写错改对了就不再出现）。
- 改采集/预处理后必须在板上跑自检：`yolov8_camera --config config.json --self-test --no-display` + 短 `--max-frames` 冒烟（详见 `vision/yolov8_adjudicator/AGENTS.md` 与 README）。
- LLM 复核的裁决优先级（共识/复问/平局保护/回退）由代码与游戏 profile 决定，与这两个文件无关，见 dice 参数说明第 5 节。
