# tts_moss_nano 参数说明

`backend/components/tts_moss_nano/config.json` 是本地 MOSS-TTS-Nano 引擎的组件层配置（JSON 无注释，本文档就是它的注释）。**改任何字段后需重启**（`stop_web.sh && start_web.sh`，启动脚本会顺带拉起 MOSS bridge 进程）。运行/切换/启停命令见同目录 `README.md`；通用切换手册见仓库根目录 `TTS配置与切换指南.md`。

```json
{
  "runtime": {
    "kind": "local",
    "root": "tts/moss-tts-nano",
    "model_dir": "models/MOSS-TTS-Nano-100M-ONNX-xslim-dynq",
    "host": "127.0.0.1",
    "port": 18082,
    "base_url": "http://127.0.0.1:18082"
  },
  "voice": {
    "mode": "clone",
    "name": "Junhao",
    "reference_audio": "voice/warm.wav"
  },
  "generation": {
    "max_new_frames": 120,
    "voice_clone_max_text_tokens": 24,
    "first_chunk_text_tokens": 16,
    "seed": 1234
  },
  "startup": {
    "warmup_text": "你好，这是 MOSS TTS Nano 在 K3 上的演示。",
    "start_timeout_seconds": 300
  },
  "limits": {
    "request_timeout_seconds": 120
  },
  "execution_provider": {
    "name": "spacemit",
    "intra_thread_num": 4,
    "inter_thread_num": 1,
    "intra_thread_affinity": "8;9;10;11",
    "disable_op_type_filter": ""
  }
}
```

## 字段说明

### runtime（本地 bridge）

| 字段 | 当前值 | 说明 |
|---|---|---|
| `kind` | `local` | 本地引擎（`start_web.sh` 按 manifest 引用自动拉起/停止 bridge 进程） |
| `root` | `tts/moss-tts-nano` | MOSS runtime 根目录，**仓库相对路径**（runtime 源码在仓库内，模型文件按该目录 .gitignore 留在板上） |
| `model_dir` | `models/MOSS-TTS-Nano-100M-ONNX-xslim-dynq` | 模型目录，**相对 root**；留空则自动探测 packaged 布局 |
| `host` / `port` / `base_url` | 127.0.0.1 / 18082 | bridge 监听地址。**校验强制 loopback**（本地引擎不允许指到别的机器，防后端变代理） |
| — | — | pid/log 落在 `.runtime/moss-tts-18082.*` |

### voice（音色）

| 字段 | 当前值 | 说明 |
|---|---|---|
| `mode` | `clone` | `builtin`（内置音色，忽略 reference_audio）/ `clone`（启动时加载参考 WAV，合成时复用其音频编码）。**换音色/换参考音频 = 改这里 + 重启** |
| `name` | `Junhao` | 内置音色名（clone 模式下作展示用途） |
| `reference_audio` | `voice/warm.wav` | 克隆参考音频，**相对 root**；clone 模式必填（缺了启动报错） |

### generation（生成参数）

| 字段 | 当前值 | 说明 |
|---|---|---|
| `max_new_frames` | `120` | 单次生成的最大语音帧数（输出长度上限，防超长生成失控） |
| `voice_clone_max_text_tokens` | `24` | 克隆模式单次合成的文本 token 上限（超长文本按此切块） |
| `first_chunk_text_tokens` | `16` | 首个 chunk 的文本 token 数——**调小 = 首包更快**（流式首延迟），调大 = 首包更完整 |
| `seed` | `1234` | 随机种子（固定值保证同文本合成稳定） |

### startup / limits

| 字段 | 当前值 | 说明 |
|---|---|---|
| `startup.warmup_text` | `你好，…演示。` | bridge 启动后的预热文本（首次合成慢是正常的，预热把冷启动代价提前吃掉） |
| `startup.start_timeout_seconds` | `300` | 拉起 bridge + 加载模型的等待预算（板端冷启动可能要一两分钟） |
| `limits.request_timeout_seconds` | `120` | 单次合成请求超时 |

### execution_provider（SpaceMIT EP 加速）

| 字段 | 当前值 | 说明 |
|---|---|---|
| `name` | `spacemit` | 标识用途（代码不读取，实际走 EP 由模型决定） |
| `intra_thread_num` | `4` | EP intra 线程数（与绑核数保持一致为宜） |
| `inter_thread_num` | `1` | EP inter 线程数 |
| `intra_thread_affinity` | `8;9;10;11` | EP 线程绑核，**分号分隔**（A100 加速核簇）。注意：实测 EP 线程池可能扩展占用整个 8-15 簇——改这里后要用 `/proc/<pid>/task/*/status` 的 `Cpus_allowed_list` 采样验证是否真按预期绑定 |
| `disable_op_type_filter` | `""` | 禁用 EP 某类算子的开关（空 = 不禁用；如 `"Conv"`），排障用 |

## 其他须知

- **只支持 `speed=1.0`**（引擎无通用语速控制），manifest 里对 MOSS 台词写别的 speed 会被拒。
- 单会话引擎：bridge 串行处理请求；同一时间只有一条台词在合成。
- 音频为 chunk 级流式（逐 chunk 发 WAV 帧），不是逐 codec 帧真流式。
