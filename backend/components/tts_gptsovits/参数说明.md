# tts_gptsovits 参数说明

`backend/components/tts_gptsovits/config.json` 是远程 GPT-SoVITS 引擎的组件层配置（JSON 无注释，本文档就是它的注释）。**改任何字段后需重启后端**；哪句话用它由游戏 manifest 决定（`providers.tts_remote` 槽位或单条台词钉 `provider`）。

服务端部署与完整 API 参数含义见仓库根目录 `TTS接口文档.md`，切换/混用手册见 `TTS配置与切换指南.md`。

```json
{
  "runtime": {
    "kind": "external",
    "base_url": "http://100.95.19.17:9873"
  },
  "request": {
    "text_lang": "zh",
    "streaming_mode": 3,
    "text_split_method": "cut5",
    "timeout_seconds": 120,
    "top_k": 15,
    "top_p": 1.0,
    "temperature": 1.0,
    "repetition_penalty": 1.35,
    "seed": -1,
    "fragment_interval": 0.3
  },
  "voice": {
    "name": "demo_female_zh"
  },
  "audio": {
    "sample_rate": 32000,
    "channels": 1
  }
}
```

## 字段说明

### runtime（服务地址）

| 字段 | 当前值 | 说明 |
|---|---|---|
| `kind` | `external` | 外部服务（无本地进程，`start_web.sh` 不需要拉起它，远程主机关机只是健康超时，不影响其他功能） |
| `base_url` | `http://100.95.19.17:9873` | GPT-SoVITS v2ProPlus 服务（Tailscale 内 GPU 主机，9873 克隆模式按音色名调用）。安全约束：请求只允许访问**该 origin** 且路径仅限 `/tts`、`/voices` 白名单，拒绝重定向——改地址就改这一处 |

### request（合成请求参数）

| 字段 | 当前值 | 说明 |
|---|---|---|
| `text_lang` | `zh` | 文本语言（混合中英时引擎按切分处理） |
| `streaming_mode` | `3` | 流式模式。3 = 裸 PCM 流（首包最快，适合边收边播；provider 收到 int16 PCM 后按 `audio` 采样参数包 WAV 帧发给前端） |
| `text_split_method` | `cut5` | 服务端文本切分方式（各 cut 含义见 `TTS接口文档.md` 的切分表） |
| `timeout_seconds` | `120` | 单次合成请求超时 |
| `top_k` / `top_p` / `temperature` / `repetition_penalty` | 15 / 1.0 / 1.0 / 1.35 | 采样参数（服务端推理侧） |
| `seed` | `-1` | 随机种子，-1 = 每次随机 |
| `fragment_interval` | `0.3` | 分片间隔（秒） |

### voice / audio

| 字段 | 当前值 | 说明 |
|---|---|---|
| `voice.name` | `demo_female_zh` | **音色名必须已在服务端注册表里**（注册表 CRUD 见 `TTS接口文档.md`）。必填：没配音色名时合成请求直接校验报错 |
| `audio.sample_rate` | `32000` | PCM 包帧时声明的采样率，须与服务端实际输出一致 |
| `audio.channels` | `1` | 声道数 |

## 其他须知

- 上游串行排队（服务端单会话），多个请求会依次处理；`stream()` 内部有模块级锁。
- 本 provider 支持 `speed` 调节（0.5~2.0，请求参数透传），这是它相对 MOSS 的差异点。
- 健康检查 = 访问 `/voices` 验证服务可达，见 `/api/tts/health?provider=tts_gptsovits`；远程主机关机时表现为健康超时（无害，骰子台词当前全是 `tts_local`/`audio`）。
