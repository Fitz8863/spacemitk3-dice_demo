# asr_sensevoice 组件参数说明

`backend/components/asr_sensevoice/` 是 **SenseVoice 本地 ASR**：非流式识别器 + 能量 VAD 断句的常驻引擎。引擎对（`arecord | asr_pipe_demo --vad --jsonl`）由后端启动预热并全程常驻，"会话"是引擎上的瞬时路由切换（回合意图 ↔ 待机唤醒 ↔ 列表选游戏），与 asr_zipformer 同一套契约。**与全局唯一槽 `providers.asr` 二选一**（引擎独占麦克风）。

## 引擎与模型

- 引擎源码：`asr/sensevoice-x100/`（板上 `mkdir build && cd build && cmake .. -DBUILD_PYTHON_BINDINGS=OFF && make -j8 asr_pipe_demo`）
- 模型：`asr/sensevoice-x100/model/`（gitignore，~232MB，重建方式见该目录 `.gitignore` 注释）

## config.json

```json
{
  "schema_version": 1,
  "runtime": {
    "binary": "asr/sensevoice-x100/build/bin/asr_pipe_demo",
    "working_dir": "asr/sensevoice-x100",
    "model_dir": "asr/sensevoice-x100/model",
    "language": "auto",
    "core_arch": "x100",
    "num_threads": 2,
    "cpu_affinity": "6,7",
    "capture": { "device": "default", "sample_rate": 16000, "channels": 1, "format": "S16_LE" },
    "vad": { "enabled": true, "rms": 400, "pause_ms": 600, "max_ms": 8000 },
    "start_timeout_seconds": 30,
    "terminate_grace_seconds": 5
  }
}
```

| 字段 | 当前值 | 说明 |
|---|---|---|
| `runtime.binary` | `asr/.../asr_pipe_demo` | 管道引擎二进制（stdin 裸 PCM → stdout JSONL），仓库相对路径 |
| `runtime.working_dir` / `model_dir` | `asr/sensevoice-x100[/model]` | 子进程工作目录 / 模型目录（仓库相对；模型下载重建见引擎目录 .gitignore） |
| `runtime.language` | `auto` | `zh`/`en`/`ja`/`ko`/`yue`/`auto`（auto 支持中英混合） |
| `runtime.core_arch` | `x100` | **EP 推理线程的目标核群**：`x100`（通用核 0-7，不与 moss/yolo 抢 A100）/ `a100`（算力核 8-15，EP 默认行为）/ `auto`（同 a100）。想"用算力核跑 ASR"就设 `a100` |
| `runtime.num_threads` | `2` | 推理线程数（映射引擎 `--threads`；X100/不绑核模式生效，**A100 绑核时自动=核数**）。实测短句 2 与 4 线程无差异 |
| `runtime.cpu_affinity` | `"6,7"` | **绑核模式**（对齐引擎仓库 run_mic_asr.sh）：`"6,7"` 等 X100 核列表（0-7，任意个数）→ taskset 全进程独占；`"8,9"` / `"10"` A100 核（8-15，**仅 1 或 2 个**）→ EP 推理线程一核一线程精确绑定（环境变量下发，taskset 够不到 A100），自动 `--threads=核数`、要求 `core_arch` 为 a100/auto；`""` / `"none"` → 不绑核。默认 `6,7` = ASR 独占两个 X100 核，其余留给应用 |
| `runtime.capture.*` | default/16000/1/S16_LE | arecord 采集参数（16000·单声道·S16_LE 是引擎硬契约） |
| `runtime.vad.rms` | `400` | 语音判定 RMS 阈值（映射引擎 `--vad-thresh`；环境嘈杂调大） |
| `runtime.vad.pause_ms` | `600` | 停顿多少毫秒判定一句结束（映射 `--pause 0.6`） |
| `runtime.vad.max_ms` | `8000` | 单句最长毫秒数，超过强制断句（映射 `--max-utt 8.0`） |
| `runtime.vad.enabled` | `true` | **必须 true**：引擎的非 VAD 模式是定时断句，不适合指令监听（校验拒绝 false） |
| `runtime.start_timeout_seconds` | `30` | 预热等待 ready 事件的超时（模型加载 ~2-3s + warmup；超时**拒启**） |
| `runtime.terminate_grace_seconds` | `5` | 停止引擎的优雅退出宽限 |

### 绑核组合速查

| 想要的效果 | 配置 |
|---|---|
| ASR 独占 X100 两个核（默认） | `cpu_affinity: "6,7"` + `core_arch: "x100"` |
| 不绑核，EP 线程在 X100 0-7 浮动 | `cpu_affinity: "none"` + `core_arch: "x100"` |
| **用 A100 算力核跑 ASR**（浮动 8-15） | `cpu_affinity: "none"` + `core_arch: "a100"` |
| A100 精确绑定两核（推理最快） | `cpu_affinity: "8,9"` + `core_arch: "a100"` |
| A100 单核最省资源 | `cpu_affinity: "10"` + `core_arch: "a100"`（自动单线程） |

## 行为特性（与 zipformer 的差异）

- **非流式**：说完一句（停顿 600ms）才识别，端到端延迟 ≈ 停顿 0.6s + RTF×句长（X100 实测 RTF 0.40-0.44），比 zipformer（流式增量）慢约 0.5s。
- **待机成本≈0**：无人说话时不做任何推理（zipformer 的 VAD 解码常开 ~0.6 核）。
- **ready 协议**：引擎就绪 = stdout `{"type":"ready"}` 事件（模型加载+warmup 完成后发出），prewarm 据此判定；stderr 诊断行不算就绪。
- 识别质量：中英混合较好，SenseVoice 输出自带标点（不影响短语子串匹配）。
