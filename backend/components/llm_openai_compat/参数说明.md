# llm_openai_compat 组件参数说明

`backend/components/llm_openai_compat/` 是**大模型（LLM）组件**：一个纯 HTTP 的 OpenAI 兼容聊天客户端，无本地进程、无生命周期管理。endpoint 配谁就是谁——云端 API（DeepSeek 等）、自建 vLLM 服务、llama.cpp 的 llama-server（`--port` 起 `/v1/chat/completions`）都能直接指。实现 `core/llm.py` 的 `LlmProvider` 契约（`verify` 一个结构化多模态请求），被视觉裁决器（`vision_yolov8_objdetect`）用于判胜前复核。失败诊断自 2026-09-14 起由本地证据规则生成，不再调用 LLM。

## config.json

```json
{
  "schema_version": 1,
  "endpoint": "https://api.deepseek.com/v1",
  "model": "deepseek-flash",
  "api_key": "sk-…"
}
```

| 字段 | 当前值 | 说明 |
|---|---|---|
| `endpoint` | `https://api.deepseek.com/v1` | OpenAI 兼容服务的**基础 URL**（自动补 `/chat/completions`；已带该后缀则原样使用）。启动探测打 `{endpoint}/models`。**修改需重启**（组件配置统一语义） |
| `model` | `deepseek-flash` | 默认模型名。游戏 manifest 的 `vision_profile.llm.model` 可按局覆盖（调用时透传） |
| `api_key` | `sk-…` | Bearer 凭证；空字符串 = 匿名（自建服务可无钥）。只在本组件 config，不进任何健康/结果负载 |
| `reasoning_effort` | `none` | **部署默认的思考深度**，取值 `none` / `low` / `high` / `max`：`none` 关闭思考模式（响应更快，实测也避免了思考模式下的 JSON 解析失败），其余交给端点分级。游戏 manifest 的 `vision_profile.llm.reasoning_effort` 可按局覆盖（热加载，比本文件优先）。非法值不发送，并在 `health()` 的 `reasoning_effort_error` 里说明。**改本文件需重启**（启动时读一次） |

`reasoning_effort` 会翻译成端点的 `thinking` 对象：`none` → `{"type":"disabled"}`，`low|high|max` → `{"type":"enabled","reasoning_effort":…}`。端点强制要求该对象带 `type`（只发 `reasoning_effort` 会被拒），所以不支持"只写 effort 值"。实测（deepseek-flash + 1280×720 稳定帧）：`none` 单次 1.4–3.8s，默认 (`high`) 5.3–10.5s，`low` 6.1–15.7s，`max` 24.1s。

## 运行行为

- **热切换的是槽位不是本配置**：全局 `backend/config.json` 的 `providers.llm` 决定裁决复核用哪个 LLM 组件，改槽值保存后**下一回合生效**（免重启）；本文件改 endpoint/model/key 则需重启服务。
- **启动软探测**：server 启动时对本组件做一次 `GET {endpoint}/models` 短超时探测，失败只记日志（复核自动禁用、裁决走 YOLO 兜底），**不拒绝启动**。
- 游戏语义字段（提示词、`allowed_outcomes`、超时、开关）在游戏 manifest 的 `vision_profile.llm`，不在本组件。

## 将来接入本地大模型

实现同一 `LlmProvider` 契约（如 `llm_llamacpp`：常驻 llama-server 子进程 + 启动预热），注册后改全局槽值即可切换，本组件无需改动。
