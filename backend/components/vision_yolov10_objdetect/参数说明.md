# vision_yolov10_objdetect 参数说明

YOLOv10 视觉裁决组件（v10 end-to-end 模型，石头剪刀布等手势游戏使用）。
与 `vision_yolov8_objdetect` **共享** resident 协议、profile schema 与规则引擎
（继承其 provider；共享契约见那边与本仓 `FRAMEWORK_DISPATCH.md` §3.3.1），
本文只写差异。游戏通过 manifest 的 `providers.vision_adjudicator` 覆盖选中本组件
（全局槽位默认仍是 v8）。

## 组件 config.json（`backend/components/vision_yolov10_objdetect/config.json`）

| 键 | 说明 |
| --- | --- |
| `runtime.binary` | 组件部署默认二进制：`vision/yolov10_objdetect/build/yolov10_camera`（按仓库根解析） |
| `runtime.working_dir` | `vision/yolov10_objdetect` |
| `runtime.mode` / `prewarm_camera` / `terminate_grace_seconds` | 与 v8 组件同义 |
| `events.protocol` | `jsonl-events-v2`（启动握手校验，协议不符 fail fast） |

## 游戏 runtime 配置（`backend/games/<id>/adjudicator_config.json`，本组件消费的部分）

per-game 必填声明、整份替换、缺键回落 C++ 编译期默认——三原则与 v8 相同
（§3.3）。本组件的键面：

| 键 | 说明 |
| --- | --- |
| `model` | 模型路径，相对本配置文件所在目录解析（rps：`models/yolov10n_gestures.q.onnx`） |
| `classes` | **模型词表**（字符串数组，按模型输出 id 排序）。**包内零内置词表**：`rps_mode` 或 `filter_no_gesture` 开启时必填，缺失启动报错 |
| `rps_mode` | `true` 启用词表折叠；`false` 按原始 classes 上报（id-only 通用检测形态） |
| `rps_map` | 折叠表 `{游戏标签: [源类名...]}`（多对一合法；未知类名/空标签/源类重复映射启动即报错）。**折叠发生在稳定计数之前**：palm↔stop 同为 Paper 的源类抖动不清零稳定计数。观测事件同时携带折叠后 class_id（声明序，rps 为 Paper=0/Rock=1/Scissors=2）与 label 文本 |
| `filter_no_gesture` | `true` 丢弃 `no_gesture` 类（HaGRID 兜底噪声类） |
| `conf` / `stable_frames` | 置信度阈值 / **折叠后**类别多重集需连续重复的帧数 |
| `rotate` | `{enabled, direction: cw\|ccw, angle: 90\|180}`——OpenCL kernel 采样重映射，90 度模式推流为竖屏 |
| `roi` | `{enabled, x, y, w, h}`（占推流画面比例）——模型只看该区域（手部放大约 1.8×），且只保留框中心落在区域内的检测（确定性排除机械臂半幅） |
| `camera` / `width` / `height` / `fps` / `intra_threads` / `ep_affinity` / `focus` / `zoom` / `queue_depth` | 与 v8 同义（采集规格是**旋转前**的） |
| `rtsp` | `{enabled, host, port}`——**path 不在此声明**：manifest `video.path` 经 `--rtsp-path` 恒压 |

## manifest vision_profile（Python 侧）

与 v8 同 schema（`class_map`/`participants`/`llm` 必填段、`video.path`、
`lifecycle`、`timeouts`）。rps 的 `class_map` 值按折叠后 id 书写（0=布/1=石头/
2=剪刀）——但单侧证据游戏的 pipeline 按**观测的 label 字符串**取手势，
不依赖 id 顺序。

## 裁决入口（与 v8 的差异）

- 双侧规则游戏照用 `adjudicate()`（继承，行为一致）。
- **单侧证据游戏**（agent 侧不在画面内）用 `observe()`：返回稳定观测
  `{"observations": {view_id: {...}}}`（推理已停、推流保温），或诊断契约
  `{"diagnosed": true, ...}`（超时/无稳定证据）。事件编排（verifying/
  result/holding）归游戏 pipeline。典型用法见 `backend/games/rps/pipeline.py`。

## 已知边界

- PPQ 量化图（INT8/UINT8 zero point 混用）固定 `ORT_ENABLE_BASIC` 优化级。
- 词表与模型**无法自动互验**（不解析 ONNX metadata）：成对声明是纪律，
  self-test 的 class_id 范围检查是唯一的低成本防线。
- 旋转/ROI/解码/推流的实测数据见 `vision/yolov10_objdetect/README.md`
  （前身试验工程调参结论也指向那边）。
