# 摇骰子游戏（dice）manifest 参数说明

`backend/games/dice/manifest.json` 是这个游戏唯一的游戏层配置入口（JSON 不支持注释，本文档就是它的注释）。改参数前先看第 8 节的**生效方式速查**——有的保存即生效，有的要重启。

校验兜底：manifest 写坏（JSON 语法错 / 校验不过）时，后端**保留最后一份可用配置**继续跑，日志里打 `[games] skip ...`，不会让游戏消失。

---

## 1. 游戏基本信息

| 字段 | 当前值 | 说明 |
|---|---|---|
| `id` | `dice` | 游戏 ID，必须与目录名一致（`backend/games/dice/`），加载时强校验 |
| `name` | `摇骰子` | 游戏选择页显示名 |
| `icon` | `⚄` | 选择页图标（emoji 或字符） |
| `description` | `双方各 5 颗 · 比较点数总和` | 选择页副标题 |
| `enabled` | `true` | `false` = 不出现在游戏列表（不是删除） |
| `participants` | —（继承全局） | 角色 → 摄像头画面物理侧的映射。**已上收全局配置** `backend/config.json`（桌面摆位是部署属性）；需要例外时在本 manifest 覆盖。视觉结果按此投影成 `winner_role`（PLAYER/AGENT/TIE），`select_by` 台词选择也用它 |

## 2. providers（组件槽位）—— 可选，不写即继承全局

引擎选择已上收到**全局配置** `backend/config.json`（字段说明见 `backend/参数说明.md`），骰子 manifest **不再声明槽位**。需要例外时（某游戏想用不同引擎）在本 manifest 覆盖对应槽位，优先级：台词级钉死 > 本 manifest > 全局。

| 槽位 | 当前全局值 | 用途 |
|---|---|---|
| `vision_adjudicator` | `vision_yolov8_adjudicator` | 视觉裁决器（YOLO 检测 + LLM 复核）；引擎选择在全局，游戏语义的 `vision_profile` 在本 manifest |
| `tts_local` | `tts_moss_nano` | 本地 TTS 槽（台词 `mode: tts_local` 走这里） |
| `tts_remote` | `tts_gptsovits` | 远程 TTS 槽（`mode: tts_remote`，远程 GPU 主机） |
| `asr` | `asr_zipformer` | 语音输入（识别引擎） |

注意：本地 TTS 引擎全局唯一且启动时钉死（运行期不可切换）；换引擎 = 改全局配置 + `stop_web.sh && start_web.sh`。

## 3. asr（语音输入）

| 字段 | 说明 |
|---|---|
| `asr.enabled` | 总开关。`false` = 完全不监听（无麦克风进程），按键不受影响 |
| `asr.phrases` | 意图 → 触发词表。**键必须是本状态机里声明过的意图名**（拼错会在加载时报错），内置意图 `speech_done` 不可映射。**每个可按键触发的意图都应有词表**（有契约测试守护）；同一触发词可挂多个意图（如"确定"同时挂 confirm 和 start_shake），桥接按声明顺序逐个尝试、由当前状态决定哪个生效——一词随游戏阶段自动适配 |
| `asr.select_phrases` | 可选：语音选游戏的触发词表（列表页/待机页点名本游戏用）。**不写 = 默认用游戏名**（dice 的"摇骰子"——说"我想玩摇骰子游戏"直接进对局）；写了则完全覆盖；**空数组 `[]` = 本游戏不参与语音选择**。热加载 |

匹配与生效规则：

- **匹配方式**：识别文本去空格、转小写后做**子串匹配**——说"那我就确认了"也能命中"确认"。选词避免日常高频词（如 OK 会命中 coke/joke 等英文串，且口语常见，易误触发）。
- **播报闸**：TTS 播报期间说的触发词被忽略（防止游戏自己的播报触发自己）。想跳过播报直接转状态就用按键。
- **生效时机**：`enabled` 和 `phrases` 都热加载，但**下一个回合创建时**才用新值——正在跑的一局、以及结算页"再来一局"（同一回合内跳转）都沿用创建时的快照。退回选择页重进（或刷新页面）即开新回合。
- **语音选游戏（列表页/待机页）**：常驻引擎上的第三块路由。列表页轮询 `/api/asr/select/events`，命中走与绿色按钮同一条进对局路径；待机页唤醒词与游戏名并存，**游戏名优先**（唤醒词"游戏"是"摇骰子游戏"的子串，点名句必须选游戏而非回列表）。进对局后由回合路由自动顶掉，宣报闸保证规则宣报不会误触发选择。
- 识别引擎参数（麦克风设备、VAD 灵敏度等）不在这里，在 `backend/components/asr_zipformer/config.json`（改后重启）。

## 4. voice / speed（TTS 默认参数）—— 可选，默认继承全局

默认值在全局配置 `backend/config.json`（当前 `voice: "default"`、`speed: 1.0`）。本 manifest 可顶层覆盖，单条 speech 动作可再覆盖——三层阶梯：台词 > 游戏 manifest > 全局。实际效果取决于 provider：MOSS 固定克隆音色且只支持 1.0；GPT-SoVITS 支持速度 0.5~2.0 与服务端注册音色名。

## 5. vision_profile（视觉裁决）

`schema_version: 1` 固定；`game_id` 必须等于游戏 `id`。

### vision（检测）

| 字段 | 当前值 | 说明 |
|---|---|---|
| `model` | `vision/yolov8_adjudicator/models/best.q.onnx` | YOLO 模型（仓库相对路径，EP 量化版） |
| `class_map` | `0→1 … 5→6` | YOLO 类别 ID → 骰子点数 |
| `participants` | `["LEFT","RIGHT"]` | 画面两侧标签 |
| `expected_count` | `5` | 每方期望骰子数，不足时诊断 `INCOMPLETE_OBJECTS` |
| `stable_frames` | `30` | 连续多少帧检测一致才算稳定结果（正整数） |
| `grouping` | `divider_regions` | 骰子归属左右的方式：`divider_regions`（按分界线）/ `x_midpoint`（按画面中线） |
| `divider_detection` | `true` | 黑线分界辅助检测 |

### multi_view（多机位，当前关闭）

`enabled: false`；开启时 `min_views` 要求最少机位数，`yolo_fusion: majority_vote` 为多视角多数票融合（平票 = 无赢家），`llm_images: all_stable_views` 为复核时提交全部稳定视角。

### rule（胜负规则）

`kind: numeric_compare` + `aggregation: sum`：双方点数求和比大小；`higher_wins: true` 大者胜；`tie_value: TIE` 平局输出值（**平局是算术事实，LLM 也无法推翻**）。

### llm（大模型复核）

| 字段 | 当前值 | 说明 |
|---|---|---|
| `enabled` | `true` | `false` = 纯 YOLO 模式（跳过复核，直接用 YOLO 结论） |
| `context_mode` | `single_turn_no_history` | 单轮无历史（当前唯一支持值） |
| `timeout_seconds` | `4` | 单次 LLM 请求超时（秒）。收紧可加快节奏，太紧视觉请求易超时回退 |
| `system_prompt` / `user_prompt_template` | — | 复核 prompt；输出限定 `allowed_outcomes`（LEFT/RIGHT/TIE） |
| `diagnosis_*` | — | 检测失败时的**诊断** prompt（只解释原因，永不宣布赢家），`reason_code` 限定在 `diagnosis_allowed_reason_codes` 枚举内 |

复核与 YOLO 不一致的裁决优先级：一致=共识；分歧先**复问一次**，复问仍反对且非平局才覆盖；YOLO 是平局则**永不被提升**；LLM 超时/失败回退 YOLO 结论。

> LLM 的 endpoint / model / api_key **不在这里**，在 `backend/components/vision_yolov8_adjudicator/config.json` 的 `llm` 段。

### video（浏览器画面）

`enabled: true` + `path: /dice/`：analysis 阶段页面内嵌的实时画面（WebRTC，经 mediamtx）。WebRTC 基础地址在 `vision/yolov8_adjudicator/config.json`。`protocol` 字段为历史保留。

### lifecycle（节奏）

| 字段 | 当前值 | 说明 |
|---|---|---|
| `pre_adjudication_wait_seconds` | `4` | 进入裁决前等待（秒），范围 0~300 |
| `post_result_hold_seconds` | `3` | 结果画面保持时长（秒），范围 0~300 |

### timeouts（预算熔断）

| 字段 | 当前值 | 说明 |
|---|---|---|
| `yolo_detection_seconds` | `4` | YOLO 稳定观测预算，超时走诊断流程 |
| `adjudication_seconds` | `30` | **整次裁决的总预算**（惰性熔断，超时终止并诊断） |

## 6. state_machine（状态机）

`schema_version: 1`；`initial: rules` = 回合起点。悬空的 `to` 引用、不可达状态会在加载时报错。

### 状态字段

| 字段 | 说明 |
|---|---|
| `ui` | 只允许 `view`/`title`/`copy` 三个键。`view` 是前端视图名（`[a-z][a-z0-9_]*`，对应 index.html 的 data-view），`title`/`copy` 是页面标题与提示文案 |
| `on_enter` | 进入状态时依次执行的动作序列（专用线程） |
| `duration` | 计时器时长（秒），范围 (0, 300]；到期执行 `on_expire` |
| `tick_seconds` | 计时器节拍（秒），范围 (0, 60]。前端按 `ceil(剩余/tick)` 渲染数字——摇骰前/开盖前倒计时 2.4s÷0.8s = 三、二、一，与预录语音对齐 |
| `on_expire` | 计时器到期的转换（必须与本状态 `duration` 同在） |
| `on_intent` | 按键/语音意图 → 转换表。意图名 `[a-z][a-z0-9_]*`；`speech_done` 是内置回执意图，不可在此声明 |
| `on_event` | 后端内部事件路由：`adjudication.result`（裁决成功）/ `adjudication.diagnosis`（诊断失败） |

### speech 动作参数

| 字段 | 说明 |
|---|---|
| `mode` | 三选一：`audio`（读游戏目录 WAV）/ `tts_local` / `tts_remote` |
| `audio` | `audio` 模式必填：游戏目录内**相对** .wav 路径（防目录穿越，不可绝对路径/`..`），如 `audio/停.wav` |
| `text` | `tts_*` 模式必填；`audio` 模式可附作显示文本 |
| `await` | `true` = 状态机等前端播完回执（`speech_done`）才继续，保住"停 → 开盖词 → 4 秒过场"节奏；引擎 30 秒兜底防死等 |
| `voice` / `speed` | 覆盖游戏级默认（见第 4 节） |
| `provider` | 显式钉死某 provider（覆盖槽位路由），如某句强制用远程引擎 |
| `select_by` + `cases` | `select_by: winner_role` 按裁决结果选台词，`cases` **必须覆盖 PLAYER/AGENT/TIE 三种**；case 内同样是 mode/text 等字段 |

台词占位符：`{player_score}`/`{agent_score}` 等由裁决结果渲染（只支持标量值）。

### 转换的三种形态（每个转换三选一）

- `{"to": "状态名"}` —— 跳转
- `{"exit": true}` —— 结束回合（回到游戏选择页）
- `{"actions": [...]}` —— 不跳状态，原地执行动作（如 `repeat` 重播规则）

## 7. 当前状态图

```
rules ──confirm──▶ ready ──start_shake──▶ shake_countdown ──expire──▶ shaking
  ▲                  │                        (2.4s/0.8s)                │
  │repeat=重播        │back=回到rules                                      stop_shake/expire
  │back=exit          ▼                                                       ▼
  └──────────────▶ exit    open_reveal(停!await→开盖词, 4s) ──expire──▶ vision_countdown(2.4s/0.8s)
                                                                          │expire
                              analysis ◀──────────────────────────────────┘
                            result ◀─adjudication.result│analysis_failed ◀─adjudication.diagnosis
                          new_round→ready              retry→analysis, new_round→ready, back=exit
```

## 8. 生效方式与配置文件地图

| 你改的东西 | 生效方式 |
|---|---|
| 全局配置（`backend/config.json`：引擎槽位/音色语速默认/语音总闸） | **热加载**，下一回合生效；**唯一例外：本地 TTS 引擎启动时钉死，切换需重启** |
| 本 manifest（台词/词表/ui/开关/超时等一切字段） | **热加载**：保存后**下一个回合**生效（正在跑的一局用创建时快照） |
| 组件 config（`backend/components/*/config.json`） | 重启后端（`stop_web.sh && start_web.sh`） |
| YOLO 硬件 runtime（`vision/yolov8_adjudicator/config.json`：摄像头/RTSP/WebRTC 地址） | 重启后端（常驻 runtime 随进程重启） |
| ASR 引擎参数（`backend/components/asr_zipformer/config.json`：麦克风/VAD/绑核） | 重启后端 |
| 游戏音频文件（`backend/games/dice/audio/*.wav`） | 热加载（下一局引用时读取） |

相关配置文件索引：

- 视觉组件（LLM endpoint/model/key、resident 模式）：`backend/components/vision_yolov8_adjudicator/config.json`
- TTS 各引擎：`backend/components/tts_moss_nano|tts_qwen3|tts_gptsovits/config.json`
- ASR 引擎：`backend/components/asr_zipformer/config.json`（VAD 断句参数含义见 `asr/zipformer-streaming/README.md`「断句（VAD）参数」节）
- YOLO C++ runtime：`vision/yolov8_adjudicator/config.json`
- TTS 使用与切换手册：仓库根目录 `TTS配置与切换指南.md`
