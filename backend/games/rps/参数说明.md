# 猜拳游戏（rps）manifest 参数说明

`backend/games/rps/manifest.json` 是这个游戏唯一的游戏层配置入口（JSON 不支持注释，本文档就是它的注释）。改参数前先看第 8 节的**生效方式速查**——有的保存即生效，有的要重启。

校验兜底：manifest 写坏（JSON 语法错 / 校验不过）时，后端**保留最后一份可用配置**继续跑，日志里打 `[games] skip ...`，不会让游戏消失。

> 视觉裁决器的**组件级参数说明**（词表/折叠表/旋转/ROI 等硬件文件的完整键面）在
> `backend/components/vision_yolov10_objdetect/参数说明.md`；两游戏共享的框架语义
> （槽位/状态机/语音动作）与本文档同构，可对照 `backend/games/dice/参数说明.md`。

---

## 1. 游戏基本信息

| 字段 | 当前值 | 说明 |
|---|---|---|
| `id` | `rps` | 游戏 ID，必须与目录名一致（`backend/games/rps/`），加载时强校验 |
| `name` | `猜拳` | 游戏选择页显示名 |
| `icon` | `✊` | 选择页图标（彩色 emoji） |
| `description` | `石头 · 剪刀 · 布` | 选择页副标题 |
| `enabled` | `true` | `false` = 不出现在游戏列表（不是删除） |
| `participants` | —（继承全局） | 角色 → 摄像头画面物理侧的映射（部署属性，在全局 `backend/config.json`）。**rps 的 agent 侧被 ROI 排除在识别区外**（那是机械臂的位置），视觉只认玩家的手；胜负投影按此映射成 `winner_role` |

## 2. providers（组件槽位）——rps 是唯一声明覆盖的游戏

其余槽位不写即继承全局 `backend/config.json`；rps **必须**声明视觉槽位覆盖（2026-09-21 视觉集成起，有契约测试钉住）：

| 槽位 | 本 manifest 值 | 全局默认值 | 用途 |
|---|---|---|---|
| `vision_adjudicator` | **`vision_yolov10_objdetect`** | `vision_yolov8_objdetect` | **rps 用 v10 独立视觉包**（手势模型 + 词表折叠 + 旋转 + ROI）；dice 等其他游戏继续走全局默认的 v8 包。双包共存互不影响，切换游戏时 runtime 必然重建（共用摄像头） |
| `tts_local` / `tts_remote` / `asr` | 不写（继承全局） | `tts_moss_nano` / `tts_gptsovits` / `asr_sensevoice` | 同 dice |

> 加载时的 vision_profile 校验也按这条声明路由：声明了 `vision_yolov10_objdetect`
> 就用 v10 组件包的校验器（两个包当前共享同一 schema）。**改这一行后需要重启后端**
> ——组件实例在启动时创建（见第 8 节）。

## 3. asr（语音输入）

**开关不在本 manifest**：是否启用语音由全局 `backend/config.json` 的 `asr_enabled` 唯一决定；本 manifest 只声明这个游戏的触发词表。

| 字段 | 当前值 | 说明 |
|---|---|---|
| `asr.phrases.confirm` | 确认/确定/OK/明白了/… | rules 页按绿键同款意图 |
| `asr.phrases.repeat` | 重复/再来一遍/再听一次/… | 重播规则宣读 |
| `asr.phrases.new_round` | 再来一局/下一局/next round/… | result / analysis_failed 页 |
| `asr.phrases.retry` | 重试/重新/重新来一遍/… | analysis_failed 页的"重新识别" |
| `asr.phrases.back` | 返回/退出/back/… | 退回游戏列表 |

匹配规则与 dice 相同（去空格转小写子串匹配、播报闸、下一回合快照生效）。rps 的状态机里**没有** `start_shake`/`stop_shake` 意图——出拳节奏由 `play` 状态的口令 `duration` 驱动，不需要玩家按钮介入。游戏选择语音（`game_select.phrases`）在全局配置——rps 目前未登记选择词（`dice: [摇骰子,骰子]`），要加就在全局配置按同款格式补 `rps: [...]`。

## 4. voice / speed（TTS 默认参数）—— 可选，默认继承全局

三层阶梯（台词 > 游戏 manifest > 全局）与 dice 相同；当前 rps 未覆盖，继承全局 `voice: "default"`、`speed: 1.0`。

## 5. vision_profile（视觉裁决）

`schema_version: 1` 固定；`game_id` 必须等于游戏 `id`。

| 顶层字段 | 当前值 | 说明 |
|---|---|---|
| `runtime_config` | `backend/games/rps/adjudicator_config.json` | **rps 专属的 C++ runtime 配置**（仓库相对路径，**必填**）。由 **v10 包**消费：模型/词表/折叠表/旋转/ROI/硬件全在这份文件里，逐键说明与调参速查见同目录 `adjudicator_config参数说明.md`；组件视角的键面见 `backend/components/vision_yolov10_objdetect/参数说明.md` |

> **rps 与 dice 的裁决路径根本不同（单侧证据型）**：agent 侧在画面外（ROI 只保留下半
> 幅=玩家+桌台，上半幅是机械臂的位置，被确定性排除），所以**不能走 dice 那套
> "双侧分组 → 规则比较"的通用管线**（`categorical_relation` 要求两侧都有值，缺一侧
> 直接报错）。rps 的 `pipeline.py` 调 provider 的 `observe()` 只拿玩家的稳定观测
> （最高置信度检测的折叠标签就是玩家出的拳），agent 的手势由**程序**给（当前随机桩，
> 那一行就是将来给机械臂下发指令的位置），比较与投影在 `games/rps/result.py`。

### vision（检测语义）

| 字段 | 当前值 | 说明 |
|---|---|---|
| `class_map` | `0→布, 1→石头, 2→剪刀` | 折叠后类别 ID → 手势（**声明性字段**：rps 的 pipeline 按观测事件的 `label` 文本取手势，不依赖 ID 顺序；ID 序来自 `rps_map` 的声明序=字母序）。**不可写 `model`/`conf`/`stable_frames` 等运行参数**——它们住在 `adjudicator_config.json`，写回来会被校验器拒载 |
| `participants` | `["LEFT","RIGHT"]` | 画面两侧标签（schema 必填；rps 只消费其中玩家一侧的投影语义） |

> **稳定判定语义（与 dice 的关键差异）**：dice 是"分界线 + 每侧恰好 5 颗 + 分侧点数
> 与上帧一致"；rps 是 v2 的**类别多重集连续 `stable_frames` 帧不变**，且多重集取
> **折叠后**的三个游戏标签——玩家从 palm 换到 stop（同算"布"）不会清零稳定计数。
> `stable_frames: 15`（约 0.7 秒 @24fps 推理）住在 `adjudicator_config.json`。

### multi_view（多机位）

`enabled: true, min_views: 1`：当前单机位（与 dice 同款声明，保持 schema 一致）。

### llm（大模型复核）

| 字段 | 当前值 | 说明 |
|---|---|---|
| `enabled` | `false` | **rps 无复核**（单侧证据型游戏，走 observe 路径根本不进 LLM 尾段）。`llm` 段及其必填字段（`context_mode`/`timeout_seconds`/`system_prompt`/`user_prompt_template`/`allowed_outcomes`）仍须写全——校验器强制，字段写空/写 `null` 会拒载整个游戏 |
| 其余字段 | — | 当前是满足校验的占位值；将来若想开复核需要先把 rps 管线接回 `adjudicate()` 路径（双侧规则），仅翻开关不生效 |

### video（浏览器画面）

| 字段 | 当前值 | 说明 |
|---|---|---|
| `enabled` | **`false`** | **用户 2026-09-21 晚拍板关闭**（调试期定下的部署值）：浏览器页面不显示识别画面，识别与 RTSP 推流照常（画面仍可用 `ffplay rtsp://<板端IP>:8554/rps/det` 看）。前端 `web/games/rps.js` 的 video 事件处理保留——**要开画面只翻这个开关（热加载），路径与前端代码都不用动** |
| `path` | `/rps/det` | 推流挂载点。mediamtx 的 `all_others` 规则覆盖，无需改服务配置；**画面是竖屏 1080x1920**（相机横装、rotate 90cw） |

### lifecycle（节奏）

| 字段 | 当前值 | 说明 |
|---|---|---|
| `pre_adjudication_wait_seconds` | `0` | 进入裁决前不额外等待——出拳口令念完（play 的 await）+ 0.4s 已是节奏的一部分，手势那时就该就位 |
| `post_result_hold_seconds` | `2` | 结果画面保持（holding 倒计时）时长 |

### timeouts（预算熔断）

| 字段 | 当前值 | 说明 |
|---|---|---|
| `yolo_detection_seconds` | `6` | 稳定观测预算：手势保持 ~1 秒（15 帧）即可稳定，余量给识别起步。无手/未稳定 → 超时诊断 `NO_OBJECTS_DETECTED`/`UNSTABLE_DETECTION` |
| `adjudication_seconds` | `15` | 整次裁决总预算（惰性熔断） |

## 6. state_machine（状态机）

`schema_version: 1`；`initial: rules` = 回合起点。状态/转换/speech 动作的通用字段与 dice 完全同构（见 `backend/games/dice/参数说明.md` 第 6 节），此处只列 rps 特有语义：

| 状态 | 特有语义 |
|---|---|
| `rules` | 宣读猜拳规则；`confirm`（绿键/Enter/语音）进 `play`，**无 after_speech 闸**（老玩家可打断宣读直接开始——2026-09-18 拍板的决策，契约测试钉着） |
| `play` | 出拳口令 `石头，剪刀，布。` 是 **`await: true`** 的 tts_local 台词：念完（前端回执）才算完，随后 `duration: 0.4` 到期进 `analysis`。**玩家在念到「布」时亮手势**。无按键意图（出拳节奏不需要按钮） |
| `analysis` | `on_enter` = 播"正在判定胜负" + `adjudicate` 动作 → 调 `games/rps/pipeline.py`（observe 单侧路径，见第 5 节） |
| `analysis_failed` | 诊断失败页：`retry`（蓝键/↓ 重试）、`new_round`（直接回 `play` 不重读规则）、`back` 退出。**retry→analysis 会再跑一次完整检测** |
| `result` | `select_by: winner_role` 三分支台词（PLAYER/AGENT/TIE 必须全覆盖），占位符 `{player_choice}`/`{agent_choice}`；`new_round` → `play` |

## 7. 当前状态图

```
rules ──confirm──▶ play(口令 await‖0.4s) ──expire──▶ analysis
  ▲                  ▲                                │
  │repeat=重播        │new_round                       ├─adjudication.result──▶ result
  │back=exit         │(result/failed页)               └─adjudication.diagnosis──▶ analysis_failed
  └──────────────────┴──new_round(直回play，不重读规则)          retry→analysis, new_round→play, back=exit
```

## 8. 生效方式与配置文件地图

| 你改的东西 | 生效方式 |
|---|---|
| 本 manifest（词表/台词/ui/超时/lifecycle/video 开关等一切字段） | **热加载**：保存后**下一个回合**生效（正在跑的一局用创建时快照） |
| `providers.vision_adjudicator` 覆盖行 | **重启后端**（`stop_web.sh && start_web.sh`）——组件实例在启动时创建 |
| rps 的 runtime 配置（`backend/games/rps/adjudicator_config.json`：**模型/classes 词表/rps_map 折叠表/conf/stable_frames/rotate/roi**/摄像头/焦距/RTSP） | **改后下一回合生效，无需重启后端**——文件 mtime 已进 runtime 签名，自动重建常驻进程；正在跑的一局仍用旧参数。**词表/折叠表改完必须过下一回合的启动校验**（未知类名/源类重复映射会在 runtime 启动时报错，那一局裁决直接失败） |
| 全局配置（`backend/config.json`：participants 摆位/语音总闸/其余槽位） | 热加载，下一回合生效 |
| v10 组件 config（`backend/components/vision_yolov10_objdetect/config.json`：二进制路径/协议声明） | 重启后端 |
