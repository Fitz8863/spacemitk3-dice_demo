# 全局配置 backend/config.json 参数说明

`backend/config.json` 是**项目级部署配置**（JSON 无注释，本文档就是它的注释）：描述"这台演示台跑什么引擎"，对所有游戏生效。游戏自身的玩法配置在 `backend/games/<游戏>/manifest.json`（见各游戏的 `参数说明.md`），引擎内部参数在 `backend/components/<组件>/config.json`。

```json
{
  "schema_version": 1,
  "providers": {
    "tts_local": "tts_moss_nano",
    "tts_remote": "tts_gptsovits",
    "asr": "asr_zipformer",
    "vision_adjudicator": "vision_yolov8_adjudicator"
  },
  "voice": "default",
  "speed": 1.0,
  "asr_enabled": true
}
```

## 字段说明

| 字段 | 当前值 | 说明 |
|---|---|---|
| `schema_version` | `1` | 固定值 |
| `providers.tts_local` | `tts_moss_nano` | 本地 TTS 引擎槽位（台词 `mode: tts_local` 走这里）。合法值：`tts_matcha`（轻量，≈240–360 MB）/ `tts_moss_nano`（默认）/ `tts_qwen3`；**启动时钉死 + 强制预热（失败拒启）** |
| `providers.tts_remote` | `tts_gptsovits` | 远程 TTS 引擎槽位（`mode: tts_remote`） |
| `providers.asr` | `asr_zipformer` | 语音识别引擎槽位（**全局唯一**：启用游戏覆盖必须与全局一致，否则启动拒绝/热加载拒换——引擎独占麦克风） |
| `providers.vision_adjudicator` | `vision_yolov8_adjudicator` | 视觉裁决器槽位（引擎选择在此；游戏语义的 vision_profile 仍在游戏 manifest） |
| `participants` | `player→LEFT`、`agent→RIGHT` | **玩家/Agent 的物理位置映射**——桌面怎么摆是部署属性，不随游戏变；游戏 manifest 可覆盖（如某游戏 Agent 在左边） |
| `voice` / `speed` | `default` / `1.0` | TTS 默认音色/语速（游戏 manifest 与单条台词可逐级覆盖） |
| `asr_enabled` | `true` | **语音输入总闸**：true 时 ASR 引擎开机常驻预热（与本地 TTS 预热并行，失败拒绝启动）；false 时引擎不拉起、语音输入全部失效，运行期翻闸由下次路由切换懒恢复。与游戏各自 `asr.enabled` 是 AND 关系 |
| `standby.enabled` | `true` | 待机页功能总开关（false = 永不待机） |
| `standby.idle_seconds` | `120` | 游戏列表页空闲多少秒进入待机（5~3600，热加载） |
| `standby.boot_standby` | `true` | **刷新页面默认进待机页**（true）或游戏列表（false） |
| `standby.wake_phrases` | `小骰子`/`醒醒`/`开始游戏` | 待机页**语音唤醒词**：待机时服务端单独开麦监听，说到任一唤醒词即唤醒回列表（唤醒只回列表不进游戏；按键/触摸唤醒始终可用）；不配置则纯按键唤醒 |

## 优先级阶梯（全局是默认层，越靠近使用点优先级越高）

| 参数 | 高 → 低 |
|---|---|
| provider 槽位 | 台词级钉死 `provider` 字段 > 游戏 manifest 槽位 > **全局** |
| participants | 游戏 manifest > **全局** |
| voice / speed | 台词动作字段 > 游戏 manifest > **全局** |
| 语音开关 | **全局 `asr_enabled`** AND 游戏 `asr.enabled` |

游戏 manifest 不写某槽位即继承全局——骰子游戏现已完全依赖全局槽位；需要例外时在游戏 manifest 里覆盖对应槽位即可。

## 生效方式（重要）

- **文件本身热加载**（mtime 检测，坏配置保留最后可用版本），影响下一个回合。
- **例外——本地 TTS 引擎**：启动时解析一次并**钉死整个进程生命周期**。运行期改 `tts_local`（或游戏覆盖）不会切换引擎，只打漂移日志——切换本地 TTS 必须 `stop_web.sh && start_web.sh`。远程 TTS / ASR / 视觉槽位无进程钉死问题，热加载正常生效。
- **唯一性约束（全面封口）**：引用面（全局槽位 + 各启用游戏槽位 + **台词级 `provider` 钉死**）出现**多个不同的本地 TTS 引擎**时，后端拒绝启动；manifest 热加载时同样拒换（保留最后可用配置）。本地引擎是重量常驻进程，一台演示机只跑一个；远程引擎按句混用不受限。
- **本地引擎强制预热**：被 pin 的引擎在 HTTP 开监听前完成拉起+预热（tts_matcha 约 3.5 秒），失败即拒绝启动——不会带着哑巴语音上场。
- 改引擎内部参数（地址/模型/VAD 等）仍去组件各自的 `config.json`，改后重启。

## 切换引擎操作示例

```bash
# 例：本地 TTS 从 MOSS 换到 Qwen3
# 1. 改 backend/config.json 的 providers.tts_local 为 "tts_qwen3"
# 2. 重启（本地 TTS 需重启；同时会停旧引擎起新引擎）
scripts/stop_web.sh && scripts/start_web.sh
```
